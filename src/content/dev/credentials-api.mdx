# Credentials API

De huidige badge-infrastructuur en de eisen voor veilige externe uitgifte.

<Callout type="warning" title="Uitgifte staat niet open">
Er is nog geen geautoriseerd issuance-endpoint. De applicatierol heeft bewust geen INSERT-recht op app_issued_credentials. Een client_id uit een verzoek is nooit bewijs van de uitgever.
</Callout>

## Het aanwezige gegevensmodel

De voorwaartse migratie `0153_app_issued_credentials.sql` definieert de types `badge`, `certificate` en `diploma`. Ze koppelt een uitspraak aan een ontvanger en OIDC-client. Dit is een broncodemodel, geen bevestiging dat de migratie in iedere omgeving is toegepast.

```typescript
type AppCredential = {
  id: string;
  clientId: string;
  type: "badge" | "certificate" | "diploma";
  title: string;
  description: string | null;
  imageUrl: string | null;
  issuedAt: string;
  showOnName: boolean;
  appName: string;
  issuerHandle: string | null;
};
```

Een `request_key` is uniek per client en vormt het opslagfundament voor idempotentie. Dat maakt een willekeurig herhaald HTTP-verzoek nog niet veilig: het toekomstige endpoint moet de client bewijzen en een conflict inhoudelijk controleren.

## Publieke projectie, geen tabeldump

`public_app_credentials(handle)` geeft maximaal 100 gepubliceerde items terug. De projectie vereist een actieve client, actieve toestemming, een niet-geblokkeerde gebruiker en acceptatie door de ontvanger. De appsectie en het profiel moeten openbaar zijn; ingetrokken items worden uitgesloten.

De ontvanger mag acceptatie en naamweergave veranderen, maar niet de titel of de uitspraak van de uitgever. De bestaande databaserichtlijnen en tests bewaken die scheiding.

## Vereisten vóór externe uitgifte

| Grens | Verplichte controle |
| --- | --- |
| Uitgever | Geauthenticeerde client met expliciete issuance-capability |
| Ontvanger | Geautoriseerde mapping van pairwise subject; geen onbewezen UUID uit de payload |
| Inhoud | Begrensde titel, beschrijving en type; veilige afbeeldingafhandeling |
| Herhaling | Clientgebonden idempotentiesleutel en conflictcontrole |
| Publicatie | Afzonderlijke acceptatie en opt-in van de ontvanger |
| Intrekking | Alleen een bevoegde uitgever; publieke weergave stopt |

Een machine-token is niet automatisch bevoegd om namens een gebruiker te handelen. OIDC-loginconsent verleent niet zonder meer toestemming voor credential-uitgifte.

## Geen impliciete cryptografische standaard

Dit gegevensmodel levert geen W3C VC-proof, verificatiemethode of statuslijst. Gebruik de term cryptografisch verifieerbaar pas wanneer het bewijsformaat, de vertrouwde uitgevers en intrekkingscontrole daadwerkelijk zijn geïmplementeerd en getest.
